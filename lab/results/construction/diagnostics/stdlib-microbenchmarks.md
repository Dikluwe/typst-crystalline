# Microbenchmarks da stdlib — primeira rodada

## Escopo e reprodução

Após a revisão da suíte, o entrypoint de medição é `benches/stdlib_bench.rs`.
O launcher verifica build otimizado e debug assertions desativadas no
artefato core antes de executar o teste privado exato. Não amplia APIs
produtivas. `-- --test` verifica build/perfil/presença do teste sem amostrar;
os tempos deste documento permanecem o registro histórico da primeira rodada.


Runner test-only em `01_core/src/compiler/stdlib/registry/microbenchmarks.rs`, com L0 exclusivo. Nenhuma API produtiva foi ampliada ou otimizada nesta rodada.

```sh
cargo test --offline -p typst-core --release --lib compiler::stdlib::registry::microbenchmarks
cargo bench --manifest-path benches/Cargo.toml --bench stdlib_bench
```

Configuração: Criterion 0.5, 30 amostras, warmup 150 ms, janela solicitada 300 ms, sem plots. Criterion pode estender a janela para completar as amostras; os logs registram esse ajuste. Execução debug é rejeitada. Relatórios Criterion ficam em `target/criterion/stdlib*`.

Montagem inclui construção e destruição do Scope, inclusive os namespaces. Inputs são preparados fora do trecho cronometrado. Lookup usa scopes prontos; calc_abs mede apenas o lookup no namespace já resolvido. Chamadas usam o ponteiro nativo previamente resolvido, sem parser, dispatcher, preparação de Args ou EvalContext no tempo medido; incluem produção e destruição do valor/diagnóstico. Não são tempos de compilação de um documento nem paridade vanilla.
