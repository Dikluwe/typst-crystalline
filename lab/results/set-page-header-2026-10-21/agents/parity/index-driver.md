# Source-derived semantic construction with physical running insertions

Status: engineering review of the unapproved `agents/core/proposal.md`, not an active L0 or implementation authorization. Productive sources/L0 remain clean HEAD `63b7b96b99109b61655b373dc0d248beb7838f86`. The fresh baseline is bound by `baseline-summary.json`, including exact receipt SHA, source/binary state, UTC and observations. No product/Cargo execution was performed for this design review.

## Evidence before the design

`01_core/src/compiler/introspect/entrypoints.rs:23-52,244-284` reserves identities, walks source Content into a mutable candidate, materializes outlines and source parents, then executes runtime postprocessors and demanded Figure folds. `walk.rs:785-1011` captures style-dependent payloads and field snapshots and immediately populates stores. `populate.rs:19-311` mutates labels, counter actions/history, kind order, metadata, state, bibliography and derived projections. A later counter-only permutation cannot repair those other stores.

The unit of semantic construction is not uniquely a Location. `heading.rs:152-280` emits root and derived TOC/bookmark/label records sharing one Location. `labelled.rs:233-345` has a located raw-Ref special case and a nonlocatable-target diagnostic path; the latter can change label classification without a real Tag::Start. `walk.rs:391-404` registers generated Context execution locations without a query element/tag, while `walk.rs:1400-1422` records outline-prefix information from Styled. Source carriers, Realized originals and actual visual children have distinct traversal contracts. Location equality alone cannot identify all these operations.

`parent_index.rs:14-57` derives parents from balanced source Start/End nesting. Such nesting is not generally preserved when a parent's children span pages and running content is inserted between them. A header must not become a child of the source Figure/Block that happened to span that page. Rebuilding source parents from flattened physical-order tags is incorrect.

`CounterRegistry::observe_location/order_key`, `StateRegistry::observe_location/order_key`, and `queries.rs` already separate causal ordinal from Location numeric identity. `from_tags/counter_updates.rs:209-377` materializes Page current/final from causal actions plus physical positions; it rejects backwards/unverified physical placement of actions. `figure_counters.rs:45-146` demands actual indexed typed Figure occurrences and exact action/history prefixes. Neither component authorizes guessed histories or an ordinal compatibility fallback.

The fresh matrix establishes background → header → body → footer → foreground query/counter order, distinct raw repetitions and actual Context locations on each page. It independently establishes footer update visibility and an inert overwritten header. PDF word order for overlapping canvas layers is not a semantic ordering oracle. ADR-0073/0074 and `00_nucleo/prompts/core/compiler/layout/finish.md` retain source-derived semantic construction and separately sealed geometry; this design does not inspect FrameItem or rebuild global introspection from pages.

## Required private construction algorithm

1. **Capture one source plan without publishing stores.** Refactor the existing exhaustive semantic walker to emit a compiler-private operation plan instead of mutating a published TagIntrospector. Keep one Content partition and the existing feature delegations; do not introduce another generic container catalogue. The legacy entrypoints use the same plan in its source order, preserving current behavior. The proposed paged entrypoint supplies a validated physical interleaving. This refactor is L0-first and must preserve the pure entrypoints independently.

2. **Separate identities, source relations and construction operations.** Reserve preexisting Located identities and allocate raw occurrences through the existing compilation arena/Locator protocol once per actual insertion. Store exact captured payload, snapshot fields, lexical chain/language, source span, explicit labels, source-parent Location, original/visual role, and operation kind. Immutable source templates are not operations until actually admitted. Preserve preexisting Located aliases as aliases; do not clone their semantic action at each use. Running transport roots do not become user-query Context/Figure elements.

   A private operation enum needs distinct cases for a real root Start, generated Context execution registration, labelled-Ref registration, nonlocatable-label classification, style-derived outline metadata, and derived label/TOC/bookmark work. A Start operation carries its complete ElementInfo and IntrospectedContent snapshot. A derived operation retains the source operands required to calculate its result later, not a number/text calculated against an obsolete preliminary counter. Capture source parentage and the Label target packet explicitly during this pass. Do not rediscover a label target by searching adjacent physical tags after interleaving.

3. **Give each operation packet an opaque per-candidate event token.** This is a transient compiler construction address, never a Location, hash, callback ID or language element. Root Location is an association, not a complete token. A packet can contain a root plus its derived operations; a nonlocatable-only operation also needs a token. Token validity is scoped to the exact immutable prepared body/template generation and retained candidate. It must not be guessed from pointer equality, text, coordinates, Func name or numeric Location order.

   The draft's public `PageRunningOrderItem::Body(Location)` is therefore insufficient unless its final contract first proves a complete attachment rule for every non-root operation. The safer concrete surface is an **opaque trace** whose private events identify source operation packets; L3 transports that trace without interpreting tokens. `PageRunningTrace` can have private fields, with the proposed L1 index façade as its consumer. This changes the draft public design and must be settled before approval. Do not advertise a Location-only trace as complete and later add a new facade silently.

4. **Record actual admission at L1 semantic dispatch boundaries.** The body plan and actual layout driver share the private event-token catalogue. Emit packet admissions when the corresponding source occurrence is accepted by normal dispatch, including zero-paint update/Context/metadata occurrences and the existing Realized original-registration boundary. Nested visual descendants retain their own admissions. A semantic source carrier omitted from visual paint still has a source packet; an arbitrary dormant semantic field does not. Marginal discovery admits a separately instantiated plan only for the actual selected physical slot. Wrap body events into physical page segments and interleave selected background/header before, footer/foreground after each page segment. Plain cursor/paint positions are not event identities.

   **Implementation proof obligation:** the final scope must name the exact private token handoff at each dispatch/replay boundary. An index-only collector cannot make a no-Location operation visible to the layout trace. Possible implementation choices are an L1-private prepared-layout plan consumed alongside Content, or private compiler transport whose canonical language snapshot remains the unmodified source. Either requires an exact, collision-free hookup and negative tests for leaked transport morphology; there is no justified fallback to matching snapshots or inventing Locations. If the proposed public trace cannot be made opaque and complete with its enumerated owners, the proposal remains not approval-ready.

5. **Validate the whole transcript before order-dependent construction.** Require exact generation, complete source packet coverage, no unknown token, source-compatible ownership, real physical page association, selected slot provenance and no conflicting resolution. Rejected flow/column/subframe trials must roll back events and consumption cursors with their existing checkpoints. Deliberate aliases admit the first semantic occurrence once; repeated raw header/footer insertions are distinct. Missing physical coverage remains Pending/invariant error, never a successful empty store. A sequence of Locations is not validated merely because all currently queried Figures appear.

6. **Construct a fresh private candidate in admitted event order.** Install causal ordinals for all admitted real/execution Locations in CounterRegistry and StateRegistry **before** any history lookup. Replay real Start operations through the existing populate owner; record snapshot fields and source labels at that same admitted position. Reuse existing exact automatic/manual action classification. Replay Context execution registrations without user-query membership. Replay nonlocatable/label and derived operations at their specified packet positions, computing counter-dependent results from this candidate. Populate kind vectors, labels, metadata, citation order/backrefs, state actions, heading/figure/table projections and histories from the same sequence. No copying order-sensitive vectors or cached resolved text from a body-only preliminary index.

7. **Preserve source parents independently.** Publish parent_locations from the source relation plan, filtered only by the established actual original/visual membership rules. A marginal insertion starts its own source root; it inherits captured styles/rules, not the body parent's tag stack. Runtime tags may be a physical-order worklist with balanced packet-local pairs; they must not be passed to `build_parent_index` as though that worklist were the original source nesting. The legacy source-order path may continue to use the current balanced source tag builder.

8. **Run existing runtime folds only after all stores see admitted order.** Resolve bibliography-to-citation conversion from the complete set of admitted bodies/resolutions before semantic capture, preserving bibliography-first semantics and existing conversion limits. Materialize outline entries only after ordered headings exist. Then run the existing counter/State-display/Equation/Heading postprocessors, Figure-demand finalizer, and Page current/final materialization against the candidate physical store in their established dependency order. Explicit reads inside retained producers are replay-validated through the existing Session; do not re-evaluate source or create a parallel fixpoint solver. Page snapshots use actual physical locations and current logical page updates, not page count as final state. Demand discovery includes actual admitted running visual children and excludes dormant templates.

9. **Seal per store and publish atomically.** Positions/pages come from the same accepted candidate physical generation and use existing sub-store sealing. Source-derived semantic stores come from the validated operation plan. Only the complete accepted transaction is returned. Pending and discarded iterations preserve existing Sink retention/discard policy. No Frame/PDF extraction, global frame introspector, post-publication store mutation or newly fabricated diagnostic suppression is involved.

## Minimal ownership consequences to resolve in the proposal

The private plan/replay machinery belongs to the proposed `compiler/introspect/page_running.rs` owner, with a small internal interface to the existing walker. Existing `entrypoints.rs` must select the appropriate source-order versus admitted-order construction path; `walk.rs` must separate capture from immediate population. `populate.rs` remains the sole interpretation of root payload mutations. `heading.rs`, `labelled.rs`, `materialize_time.rs`, `parent_index.rs`, `outline_entries.rs` and `bibliography.rs` must be audited for whether their current eager operations require deferred plan operands or ordered complete input. They cannot be omitted from the exact manifest merely because the draft names only walk/populate. Their public APIs need not change.

CounterRegistry and StateRegistry may use private methods to install complete causal order before history construction. Do not expose mutable order maps or rewrite only counters. Existing from_tags callback units remain owners of their runtime logic; only a proven changed dependency/order requires their L0/source scope. Layout dispatch, Realized registration and every transaction checkpoint that carries trace state need explicit owners. The public trace/template façade must be finalized as an exact ADR-0127 gate, including canvas scope and mixed Paged/HTML bundle behavior.

The new baseline proves background/foreground participate in the same semantic sequence; a Header/Footer-only public slot enum is not a complete answer to those language results. Either include all actual admitted layers now, or preserve those measured failures as explicit separately gated obligations without claiming full running-content closure. Existing static PageRun admission must be migrated coherently to avoid counting both its old template walk and new physical insertion. Product PageRun page2→page1 is an independently measured position-store gap, not a passing preservation control.

## Acceptance for the driver itself

- Root/derived tags sharing one Location do not duplicate automatic actions, query membership or parents.
- A source parent spanning two pages retains its own source children; header/footer Context and Figures remain separate roots.
- Nonpaint Counter/State updates before/inside/after marginals affect exact corresponding get/at/final observations; Func callbacks run only through existing folds and retain diagnostics.
- Metadata, labels including duplicate-label refusal, citation/backref order, kind/native selectors and outline projections all use the same admitted order, not only Figure captions.
- Inert overwritten templates never execute callbacks, register labels/metadata or produce warnings.
- Repeated raw templates yield fresh occurrences; intentional Located aliases retain first-observation identity and source snapshots.
- A missing/duplicate/foreign token, stale candidate, malformed parent ownership or incomplete physical coverage cannot yield Complete.
- Rejected layout trials and nested flow/column/subframe replay leave no phantom event, history, warning or consumed resolution.
- All fresh fifteen bilateral sources retain their exact source bytes. Refusal and diagnostic differences stay separate from successful source properties, with no broad PDF/HTML/error normalization.

This is a concrete causal construction design with one unresolved engineering gate: the exact complete event-token handoff and resulting final opaque public trace shape must be specified and independently checked before ratification. It is more precise to expose that blocker now than to approve a Location-only list and discover unrepresented source operations during implementation.

## Cross-review constraint: transport is not automatically transparent

Independent core review identifies `layout/mod.rs:1255`, `layout/paragraph.rs:472-483` and `layout/paragraph_prepare.rs:217-239`: ordinary Located changes current Location, writes positions, and is opaque/rejected by some paragraph paths. Therefore it cannot be repurposed as an allegedly neutral packet-token wrapper. Even a catalogue-owned early intercept would require proven packet-transparent handling in all affected paragraph classifiers/collectors and matching rollback. The preferred token remains a private nonlanguage event address; no fake Location or generic transparency change follows from this design. The final exact owner list must include any transport-sensitive path actually selected. This corroborates the unresolved handoff blocker; it is not a new implementation directive.
