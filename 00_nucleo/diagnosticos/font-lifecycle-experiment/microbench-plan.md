# Font microbenchmark plan

This is a reviewable plan following the font lifecycle intervention, not a new timing dataset. Existing benchmarks and production APIs remain unchanged by this plan. Start with coverage construction, then acquisition and lookup. Read `benches/README.md`, `../benchmark-suite-review.md`, the preserved baseline audit and the current owner L0 before implementing a case.

## Questions and input identity

The controlled interval intervention improved fresh-process CLI medians by roughly 36–37%. Demand-driven discovery alone moved acquisition into eval/layout without a consistent total improvement. The remaining gap is not proof that a particular parser, vector allocation or lookup caused it. The standalone catalog probe ran substantially slower than the CLI acquisition-containing phase; its absolute time cannot be assigned to that CLI.

Use the exact recorded font files, face indices, Fontconfig configuration and SHA-256 values in `build-state.json` and `embedded-fonts.json`. Choose actual faces by those records, including Libertinus text, a large CJK face, a math face and a face with overlapping Unicode subtables when present. Do not identify a fixture only by family name. Store the chosen path, bytes hash, index, Unicode subtable formats/order, codepoint sequence hash, distinct set size and canonical coverage hash in the diagnostic fixture manifest. If a suggested face is unavailable, record that fact and the actual replacement before measuring.

Capture real cmap sequences outside the constructor timer in exactly the order consumed by `03_infra/src/fonts.rs:403`; retain duplicates between subtables. Synthetic ascending, descending, sparse, duplicate and shuffled controls test mechanisms separately and do not stand in for the real font distribution. Validate every result against an independent set oracle before timing. Compare preserved old/new source variants with the same fixture manifest; do not copy an old implementation into production or expose a new public range builder for the harness.

For shaping preflight, verify that the fixture actually contains resolvable Text items and produces shaped glyphs; a fixture with `style.font == None` can bypass the operation. Prepare first-font documents using a separate setup World, then time an equivalently configured fresh World. Do not silently reuse the setup World and call its fonts cold.

`font_info_from_bytes` and `FontSlot::get` are existing public L3 boundaries. `extract_coverage`, lower shaping helpers and reconciliation internals are private or crate-scoped. Keep those boundaries intact. If an existing owner test can measure a private operation, use its supported guarded runner; introducing such a test requires a separately scoped implementation and corresponding owner specification. A diagnostic reimplementation may test a hypothesis but cannot be presented as measurement of that private production function.

## Harness details

The locally resolved Criterion 0.5 source (`src/bencher.rs:236` and `:326`) confirms that `iter_batched` generates input before `measurement.start()` and drops returned output after `measurement.end()`. An input passed by value can nevertheless be destroyed within the routine. `iter_batched_ref` retains both the input and returned output until after measurement. Batched loops also time iteration/output collection overhead. Prefer `BatchSize::PerIteration` for acquisition and large documents; measure harness overhead for very short queries rather than subtracting an unrelated fixture.

For constructor-only cases, use setup `|| codepoints.clone()` and a routine returning the Coverage. This excludes the clone but necessarily includes disposal of the Vec consumed by the API. For slot acquisition, use a fresh slot in `iter_batched_ref` and return the Font. Do not call `get` in setup for a first-use case. Plain `iter` with a discarded return value includes that value's destruction. State these facts in each published result, not only in this plan.

Keep whole-process cold-start measurements separate from Criterion loops. Criterion warmups can initialize slots, World catalogs, allocator state and CPU caches permanently. In-memory constructor fixtures intentionally measure a warm operation; label them accordingly. No privileged cache flush or machine setting change is required by this plan. Record observed power/frequency/thermal state and filesystem warmup; a fresh process is not evidence of cold storage caches.

## Resolve the standalone-probe mismatch first

Use one diagnostic executable and identical ordered font universe to alternate four acquisition contexts: direct system loader; configured World first book; first book after equivalent library/source setup; first book after equivalent evaluation work. Keep the context work outside the acquisition timer and record its separate duration. Match embedded/project inclusion before comparing absolute times. Use fresh subprocesses and alternate order. Record user/system CPU time, faults and context switches, with frequency/power/thermal observations outside the timer. Existing public APIs suffice; do not add instrumentation APIs to production.

If the same loader remains slower without CLI preparation and converges after matched preparation, that supports a setup/cache/allocator-state explanation. If not, investigate executable linkage, compiler flags and process/machine state. The current dataset establishes none of those causes. Retain all raw results and do not deduct the old standalone probe's 173 ms paired mean gain from CLI wall time.

## Hypothesis controls

| Hypothesis | Controlled experiment | Outcome that weakens the explanation |
| --- | --- | --- |
| Sorting repeated cmap codepoints dominates coverage construction | Same real sequence and constructor API, old sort/dedup versus interval variant, off-clock clone; disclose input deallocation | Little constructor gain despite equal coverage; the end-to-end gain would need another explanation |
| Remaining vector collection materially contributes to the vanilla gap | Separate decode/collect from constructor on the same bytes, then a diagnostic streaming range union using the same parser/subtables; compare exact sets and allocations | Collection is small, or streaming does not improve the matched composition; synthetic-only wins do not establish the production cause |
| Font bytes/metadata parsing dominate after range compaction | Same file/face bytes in memory versus first public slot access, and metadata-only facade; equal cache states | Warm metadata is small or no repeatable IO-associated gap; component differences alone are not an additive CLI decomposition |
| Catalog queries dominate shaping | Warm catalog query workload matching observed document demand, alongside public warm shaping on that same document | Queries account for little time or document shaping does not track the controlled workload change |
| No-text shape/image gap is driven by legitimate metric demand | Compare documents differing only in a metric-requiring placement/context, inspect existing traces and selected geometry; use a diagnostic World wrapper to count demand without changing returned metrics | Catalog is requested equally or gap persists without demand. Do not suppress baseline/cap-height metrics or call that a parity fix |
| Reusing the World amortizes discovery across recompilation | Repeated public compilations with one World versus fresh Worlds, equal sources/fonts, file invalidation kept distinct | Discovery repeats despite retained World or another phase dominates; does not establish current CLI watch behavior |

Do not sum cases using different fonts, documents, cache states or operation counts. Reconcile phase costs only within one traced execution with disjoint boundaries. A nested font discovery duration belongs inside eval/layout and must not be added again. Full PDF export is not stream-only work. The existing `stream_bench` and `pdf_builder_bench` already use honest full-export cohort names; preserve that classification.

## Admission and repetition

Compile all existing targets with `cargo bench --manifest-path benches/Cargo.toml --no-run` before sampling; inspect actual artifact profile and hash every executable. Require opt-level 3 and disabled debug assertions/overflow checks for this comparison, neutralize ambient Rust flags, and retain the existing observation/stdlib launchers' profile checks. Never report raw debug ignored-test results.

Capture HEAD, exact tracked/untracked dirty lists and patches, source/input fingerprints before and after every block, toolchain, machine, environment, commands and executable hashes. Freeze production sources and diagnostics that implement the experiment. Discard whole blocks with fingerprint changes or concurrent tests/builds/benchmarks. Wait for a 30-second quiet gate and alternate old/new order on CPU 4 with one worker.

Use at least three separate rounds; retain every raw sample and warmup separately. Publish per-round and pooled n, mean, median, SD, p05/p95 and paired differences. Report the ADR-0115 mean/median criterion explicitly, but add a preregistered round-range check: max minus min round mean divided by their median must be at most 5% for a stable absolute-cost claim. Failure keeps the results descriptive and requires a new complete matched round set; do not rescue a claim by dropping the slow round. Allow confidence intervals for paired effects while acknowledging clock/system variation. Neither a passed unit test nor a profile guard proves timing stability.
