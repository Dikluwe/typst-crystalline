## Registered surfaces and value mapping

Native signature remains `fn native_X(ctx: &mut EvalContext<'_>, args: &Args) -> SourceResult<Value>`. `read` accepts Path/Str; `csv` and the macro family `json`, `yaml`, `toml`, `cbor`, `xml` accept Path/Str/Bytes. CSV's Bytes extension was specifically authorized by the owner with «Autorizo» on 2026-09-08; it does not authorize Symbol coercion or general CSV parity. The earlier macro extension did not itself cover read/CSV.

Register `cbor` as callable `Func::native_with_namespace("cbor", native_cbor, ns)` with `encode` bound to `Func::native("cbor.encode", native_cbor_encode)`. Existing Func field-access dispatch resolves the namespace; do not alter that dispatch. `cbor(...)` remains a decoder, `cbor.encode(any)` returns Bytes, and no csv.encode/xml.encode/read.encode is added.

Canonical JSON/YAML/TOML/CBOR mapping is null→None, bool→Bool, integer→Int(i64), real→Float, string→Str, sequence→Array and object/map/table→insertion-ordered Dict. Non-string YAML/CBOR map keys error. Out-of-i64 integers must follow measured vanilla behavior and be documented with a closing test; the historical Float expectation is not established fact. TOML datetime remains the explicitly graded RFC3339 Str mapping, not an implicit claim of rich Datetime support. CBOR byte strings map to Bytes; the former absence debt DEBT-62 is closed by Bytes materialization.

XML elements map to Dict with `tag: Str`, `attrs: Dict`, `children: Array`; text nodes are Str and the document is an Array of top-level nodes. CSV cells are always Str. Default row-type is the Type value array; dictionary treats the first record as ordered keys. Array mode treats header rows ordinarily. Both modes preserve strings, Unicode, quoting, row/field order and strict equal field counts; flexible parsing stays disabled.

CBOR encoding recursively maps None/Bool/Int/Float/Str/Bytes/Array/Dict to Null/Bool/Integer/Float/Text/Bytes/Array/Map; map keys are Text and retain insertion order. Opaque values use `Text(repr_value(v))`. In particular, Symbol and Content retain the documented dedicated-serialization divergence: do not silently replace this textual fallback with vanilla's structured form. The motivating measured cetz consumer uses numeric/string/None dict/array payloads; a real need for structured Symbol/Content requires revisiting that scope. Canonical repr fixes for State/Counter/Location/With/causal Args deliberately propagate to CBOR strings only within the proposed encoder approval scope below; this is not general CBOR parity or byte preservation.

## Read and source casts

`read(path)` and `read(path, encoding: "utf8")` return Str for valid UTF-8; invalid UTF-8 errors with `failed to convert to string (file is not valid UTF-8 in {ficheiro}:{linha}:{col})`. `encoding: none` always returns raw Bytes, including valid UTF-8. Only `"utf8"` or none is accepted: other strings report `expected "utf8" or none`; other types report `expected "utf8" or none, found {tipo}`. The old automatic UTF-8-to-Bytes fallback was refuted and revoked, not retained as an alternative. BOM/ISO encoding detection remains outside scope.

For read, invalid first positional reports `expected path or string, found <tipo público longo>`; Bytes remain invalid. The five macro decoders and CSV use `expected path, string, or bytes, found <tipo público longo>`. Use canonical public long type names and the value_span of the first positional occurrence, ignoring earlier named arguments. Preserve a legitimate detached origin or synthetic Args without occurrences; invent no range. With/Args/spread preserve the causal carrier; dispatch supplies traces. Cast validation performs no I/O, transforms no valid value and creates no new public helper/type/trait/signature or phase. Separate private read/CSV helpers are allowed; never discriminate by lexical function name, fixture or error text.

Symbol is a separately documented divergence: vanilla coerces it to Str and attempts a path read; Crystalline still rejects it with `expected path or string, found symbol` for read and `expected path, string, or bytes, found symbol` for the other loaders. The new long-name/origin formatter applies, but that is a normative effect, not Symbol parity. Do not add the coercion incidentally. Missing/excess/named validation in read and the five decoders, encoding, parsing and unrelated fields/encoders remain governed by their existing owners.

## Current CSV validation contract

Before resolution, reading or parsing, consume required first positional source and cast it as Path/Str/Bytes. Without it, a named source reports ``the argument `source` is positional`` at the first full source occurrence with hint ``try removing `source:` ``; otherwise report `missing argument: source` at args.span. With a valid positional, named source is an ordinary remainder, not a missing-argument hint.

Convert every delimiter occurrence in causal order, then every row-type occurrence, regardless of interleaving between names. First failed conversion wins; only after all succeed does the last valid occurrence win. A pre-bound invalid occurrence cannot disappear through a map overwrite. Delimiter must be one ASCII character: `expected exactly one character`, `delimiter must be an ASCII character`, or `expected string, found <tipo longo>`. Symbol delimiter remains rejected with `expected string, found symbol`; row-type Symbol reports `expected type, found symbol`. Row-type accepts Type::Array/Type::Dictionary, otherwise ``expected `array` or `dictionary` `` for wrong Type or `expected type, found {string|integer|...}` for a non-Type. Failures use that occurrence's value_span. Syntactic duplicate rejection before invocation remains unchanged.

After consuming source and all occurrences of both option names, reject the first remaining occurrence in causal order: positional `unexpected argument`; named `unexpected argument: N`. Use the full argument span, a single Error and no additional hints. Only fully valid arguments reach source resolution and the single parser. No validation failure may read or parse data.

Synthetic Args use occurrence_sequence's existing fallback: items in order, then named map order, with detached individual spans; missing uses the received aggregate span. Explicit detached stays detached. With/Args/spread/sink preserve occurrences and their origins. Loading must use args.span as received, without AST/Source inspection, message comparison or manufactured ranges. The dispatch owner `00_nucleo/prompts/core/compiler/eval/call_dispatch.md` separately owns transport of call.span() for CSV by native identity and through With. That bounded repair was required because the first candidate marked the argument list rather than the full call for eight missing-source cases. Synthetic application without AST preserves its received aggregate span.

This final order supersedes earlier preservation of unknown-before-source/options and parser-before-excess. Tests must retain both parsing without excess and rejection-before-reading with excess. Earlier parsing-plus-excess results are historical controls, not the current promised behavior. No general ordering change is authorized for other loaders.

## CSV parser causes, ordinal and position

Keep one pure decoder/parser and its public signature. UnequalLengths is `failed to parse CSV (found {len} instead of {expected_len} fields in line {line})`, with counts from the parser and line the 1-based rejected record ordinal. Include dictionary header in that ordinal, exclude ignored empty lines and quoted internal newlines; array/dictionary agree. Never substitute Position.line/byte, count raw newlines or reconstruct records. ErrorKind::Utf8 produces exactly `failed to parse CSV (file is not valid UTF-8)` for headers or data in either row mode. Match the error variant, not Display/error text/fixture. Do not prevalidate UTF-8: a prior UnequalLengths remains the winner even if a later byte is invalid. Other causes remain literal. Pure decode_csv errors remain detached and have no native positional/path suffix.

Native CSV Bytes parsing errors use the value_span of the first positional, never a named/full-call/internal-byte/second-positional span. Detached/synthetic origins remain detached. Keep the cause, hints, severity, single error and dispatch traces. Bytes never reads World. Add ` at L:C` before the final cause parenthesis, even with detached origin. Derive 1-based L/C from the parser byte offset saturated to reference u32; absent position falls back to record ordinal/column1. Impossible offsets must not panic or fabricate a position. Never derive the offset from Position.line, ordinal, valid_up_to, first invalid byte or formatted message.

Select text/binary conversion by validity of the entire buffer only after the parser selects the failure. Valid text recognizes LF/VT/FF/CR/NEL/LS/PS, treating CRLF as one break whose next line starts after LF; an offset between CR and LF remains on the previous line. Columns count characters, not bytes/UTF-16. Invalid buffers count LF in the prefix to the offset and replacement-decoded characters after the last LF; without LF in that prefix, column is 1. This applies even when the winning width error precedes the invalid byte. Do not reparse or change precedence.

Only native CSV Path/Str parsing on a buffer that is not wholly valid UTF-8 adds ` in P:L:C` before the final parenthesis. Retain resolved RootedPath once: Project uses vpath without initial slash; Package uses canonical PackageSpec plus slash-prefixed vpath. Never use physical paths, raw unresolved strings, isolated basenames or fixture names, and never resolve rooted Path again. Reuse the binary position rule above, falling back to ordinal/1 when parser position is absent. For an impossible offset retain path without invented L:C. The primary span is the first positional value_span, including With/Args/spread/sink; detached/synthetic stays detached but retains textual path/position. Preserve winning cause, ordinal, hints and traces. Do not point at invalid external bytes, use include_path as identity manufacture, add World calls for FileId or perform UTF-8 checks before parser failure.

Valid UTF-8 external-file diagnostics remain a separate open debt: vanilla uses a range in the external source, but World::read_path supplies bytes without FileId. This binary repair does not close that debt, cross-file causal Str resolution or general CSV/Path parity. Existing resolution/read errors remain literal. Str uses current_file; Path retains captured root/base. No new public API/entity/trait/dependency/flag/namespace/phase or I/O is authorized; private diagnostic context in the decoder owner is permitted.

Use existing native signature/dependencies; no global Serialize on Value, new public serializer API, crate, CLI/feature/I/O/clock/phase or World access. Decoder/namespace registration has separate ownership.

Proposed total Value partition: None/Bool/Int/Float/Str/Array/Dict recursively structured; human-readable Bytes become `bytes(N)` string; Symbol becomes Unicode, not repr; Content/LocatedContent becomes an ordered public map with func first; remaining Values use eval's canonical repr facade. TOML requires top-level Dict, omits none fields, errors on none in arrays with `failed to encode value as TOML (unsupported None value)`, emits empty dict as empty string, nonempty document with final newline, scalars before tables with stable order within each class, and measured four-space multiline pretty arrays. YAML preserves insertion and exact quoting/block scalar/indent/chomping, final newline and null/`.nan`/`.inf`/`-.inf`. Exact public output, not normalized strings, is acceptance; round-trip is only an additional control.

Proposed encoder validation consumes causal Args: every pretty occurrence converts in order and only the last valid wins. Missing value is `missing argument: value` at the call; named value uses ``the argument `value` is positional`` and hint ``try removing `value:` `` at full named span. Value/pretty casts use value_span. First remaining positional/named yields `unexpected argument` / `unexpected argument: <nome>` at full span. TOML wrong type is `expected dictionary, found <tipo>`; unsupported None-array anchors the input positional. Preserve complete frozen order/messages/hints/side diagnostics/exit/spans; dispatch transports rather than selects anchors by message. Legitimate arguments.map detached remains detached; losing origin retained by vanilla through spread/sink/With/filter is failure. Synthetic None follows Args owner's explicit policy.

LocatedContent Some must recursively serialize its authoritative func/field map without adding per-field defaults, converting to repr or runtime realization. LocatedContent None uses the legacy public tree projection; raw Content uses presence fields, never hardcoded CLI defaults. Do not restrict classification to Heading: all mandatory composite classes remain tested. Preserve complete defaults of the standard queried Heading, causal label, structured body, nested snapshot and ordering. Heading producer debt for tolerated/discarded named arguments, callbacks and unmodeled region is not repaired or masked by encoding. Snapshot transport does not certify those inputs.

CBOR retains Content/LocatedContent textual fallback, with one explicitly proposed delta: LocatedHeading Some's realized canonical repr changes the CBOR string; record it rather than adopting vanilla's structured output. Raw Content/Symbol debts and controls remain. This adds to the proposed State/Counter/Location/With/Args exceptions; it promises neither snapshot byte preservation nor general CBOR correction. Validation, Args/spans, formats, scalar/None/pretty and prior dependencies remain unchanged. A route discarding the carrier or a mandatory unrecoverable field refutes the inference that the snapshot suffices. ## Acceptance and protected boundaries

Pure decode uses literal in-memory bytes, including small generated CBOR fixtures, without disk. Preserve JSON scalar/object/array/error, YAML map/sequence, TOML string/datetime graded cases, CBOR tree/byte strings and encode round-trip, CSV array/dictionary/custom delimiter/strict-width, XML nested nodes, read UTF-8/none/invalid-encoding, Bytes-source and I/O-versus-parser controls. Match complete language values, not parser-tree mechanics.

For casts/options/CSV, freeze independent expectations before the patch; require local RED→GREEN, A/B repeated and reordered, and complete diagnostics including causes, spans, hints, traces, severity/exit. Cover first/second positional origins, named-before-positional, With/Args/spread/sink/map/filter, legitimate detached/synthetic fallback, all option occurrences, source-with/without positional, competing errors and no-I/O validation. Cover LF/CRLF/CR, multiline/empty records, Unicode and separators/BOM, invalid header/data, earlier width error followed by invalid bytes, both row types, Project/Package normalized paths, single resolution/read and protected Bytes/valid-file/other-loader controls. Do not strip suffixes or spans to claim bilateral equality. Symbol and other deliberate divergences require separate normative expectations; Unknown mandatory cases block closure.

Each former narrow CSV delta remains bounded, with its now-superseded precedence preserved only as historical evidence. Source/options/origin/ordinal/cause/position tests must retain their controls as current validation order is applied; never remove assertions to manufacture parity. Carrier sufficiency is an inference: lost origin/occurrences, wrong ordinal/position, a new public contract, need for FileId or another owner refutes a local closure and requires a new decision. Internal diagnostic corrections use ADR-0127 continuous flow with L0 first and revalidation, not a new default/phase/API or a claim of general loader parity. Public CSV Bytes approval is bounded as above; proposed encoders/snapshot still require their own approval.

Keep decode_cbor, decode_csv and RowType reexports test-only under cfg(test) in this private parent. Do not change decoder behavior or public native paths. Production/test import cleanup must pass its applicable fmt, strict Clippy and lineage gates with no new violations; it claims no performance or parity gain.
